Date: 2026-05-10

## Ravi's feedback

Ravi confirmed that the v1.2 visual output compiles and displays, but the key levels themselves are wrong.

Important user feedback:

```text
Even the key levels are very wrong.
Lower timeframe visuals do not make sense because the KLs are not calculated according to the real NCI structure.
```

## Assistant interpretation

This feedback is correct.

The current KL engine is still a preliminary pivot-based placeholder. It is not yet a real NCI key-level engine.

Current placeholder logic roughly does:

```text
recent pivot high = KL DOWN candidate
recent pivot low = KL UP candidate
```

That is not sufficient for NCI.

## Core problem

NCI KLs cannot be calculated from random recent pivots.

They must come from connected market structure:

```text
valid HH / HL / LH / LL sequence
valid breakout
valid pullback
range formation after breakout/pullback
parent event anchor
active structure leg
opposite-direction recalculation after parent break
```

## Required correction

Before further SMC/SATS development, the project needs a dedicated real NCI KL engine.

Suggested next build:

```text
v1.2.1 — Real NCI Key Level Engine Foundation
```

## v1.2.1 requirements

The next patch must stop treating every pivot as a KL.

It should introduce:

```text
1. Candidate swing extraction
2. Swing validation using impulse/pullback context
3. Connected structure sequence
4. Direction-aware KL assignment
5. Bullish KL UP from valid HL / demand-side decision
6. Bullish KL DOWN from valid HH / breakout objective
7. Bearish KL DOWN from valid LH / supply-side decision
8. Bearish KL UP from valid LL / breakdown objective
9. Range KL high / range KL low only after valid range context
10. Parent-child KL role filtering
```

## Visual rule

If a KL is not structurally valid, do not label it as KL.

Use different labels:

```text
candidate pivot
candidate range edge
unconfirmed level
```

Only confirmed NCI levels should be labelled:

```text
KL UP
KL DOWN
Parent KL
Working KL
Broken KL retest
```

## Priority correction

The project should not continue adding new features on top of wrong KLs.

Correct order:

```text
1. Fix KL accuracy
2. Then improve visual filtering
3. Then add SMC context
4. Then add SATS trend-quality layer
```

## Permanent project law

```text
Wrong KL = wrong story.
NCI key levels must be structure-derived, not pivot-derived.
```
