# v1.3.1 Failed Auto Level Feedback

Date: 2026-05-10

## Screenshot context

Ravi tested v1.3.1 on BTCUSD 15M.

The panel showed:

```text
NCI Auto v1.3.1
4H Event: Transition / wait
Hierarchy: 1H transition / wait | 15M rebuilds bullish after parent break
Confidence: Auto story active
Visible: All auto anchors shown
4H: Transition cycle | UP n/a | DOWN n/a
1H: Range cycle | KL DOWN broken -> bullish recalculation
15M: Transition cycle | Transition / wait
5M: Transition cycle | 5M transition / wait
```

Chart displayed:

```text
AUTO 1H KL DOWN around 80872
AUTO 1H KL UP around 80561
AUTO STORY Transition / wait
```

## Ravi reaction

```text
It's not making any logic. What are these levels?
```

## Diagnosis

The displayed lines were not true NCI KLs. They were latest pivot-derived range/cycle candidates.

The auto engine incorrectly promoted candidate pivots to KL labels before NCI validation was complete.

## Required correction

The script must stop drawing or naming unconfirmed pivots as KL.

The next version must separate:

```text
Candidate high / low
Confirmed KL UP / DOWN
```

## New safety rule

```text
Candidate pivots can be shown only as candidates.
Confirmed KL labels require validated NCI structure.
```

## v1.3.2 target

```text
Candidate vs Confirmed KL Guard
```

This should make the output less confident but more honest.

Correct behavior for the screenshot should be closer to:

```text
4H: no confirmed KL yet / transition
1H: candidate range only; no confirmed NCI KL
15M: transition / wait
Visible lines: Candidate High / Candidate Low, not AUTO KL
```
