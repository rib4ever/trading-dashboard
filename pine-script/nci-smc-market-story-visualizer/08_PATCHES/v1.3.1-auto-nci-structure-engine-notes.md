# v1.3.1 Auto NCI Structure Engine v1 Notes

## Purpose

v1.3.1 moves from basic automatic hierarchy toward real NCI-style automatic KL identification.

The goal is no longer manual calibration as a trading workflow.

```text
Manual calibration = optional validation only
Automatic NCI state engine = main workflow
```

## What changed from v1.3.0

v1.3.0 used a first-pass auto hierarchy engine.

v1.3.1 adds a more rule-based NCI structure engine:

```text
qualified structure legs
valid break detection
KL touch detection
parent event state
child role interpretation
state-based KL labels
```

## Key implementation idea

Do not treat every pivot as a key level.

A KL candidate is accepted only when it belongs to a qualified structure cycle:

```text
Bullish cycle
Bearish cycle
Range cycle
Transition cycle
Building cycle
```

## Auto event states

```text
KL DOWN touched -> pullback/reaction
KL UP touched -> pullback/reaction
KL DOWN broken -> bullish recalculation
KL UP broken -> bearish recalculation
Range active
Transition / wait
Continuation / building
```

## Parent-child rule

```text
4H event controls 1H interpretation.
1H event controls 15M interpretation.
15M event controls 5M interpretation.
```

Example:

```text
If 4H KL DOWN is touched and 1H is bullish,
then 1H is not automatically a 4H reversal.
It is interpreted as pullback up to parent KL.
```
