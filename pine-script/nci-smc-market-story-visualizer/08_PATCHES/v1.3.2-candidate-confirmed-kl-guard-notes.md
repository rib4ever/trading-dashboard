# v1.3.2 Candidate vs Confirmed KL Guard Notes

## Ravi feedback

Ravi tested v1.3.1 Auto NCI Structure Engine and said:

```text
It is not making any logic. What are these levels?
```

## Honest diagnosis

Ravi is correct.

The levels shown by v1.3.1 are not reliable NCI key levels yet.

They are mostly:

```text
latest qualified pivot high / pivot low candidates
```

The script is currently naming those candidate pivots as AUTO KL UP / AUTO KL DOWN too early.

## Why the logic is wrong

A real NCI KL is not simply:

```text
latest pivot high
latest pivot low
```

A real NCI KL must come from an active validated story:

```text
valid structure leg
valid breakout or rejection event
valid pullback
active parent cycle
non-obsolete level
```

v1.3.1 does not yet enforce all those gates. That is why the chart can show levels that look random.

## Immediate correction required

v1.3.2 must stop calling unvalidated pivots “KL”.

New rule:

```text
If the structure is not validated, label it as Candidate only.
Do not label it as KL.
```

## v1.3.2 required behavior

```text
1. Separate Candidate Structure High/Low from Confirmed KL UP/DOWN.
2. Only show Confirmed KL when the NCI validation gates pass.
3. If validation is missing, panel must say: Candidate only; no confirmed NCI KL.
4. Add reason field explaining why no KL is confirmed.
5. Do not build a confident market story from unconfirmed candidate pivots.
```

## Validation gates for confirmed KL

A confirmed KL requires:

```text
1. Qualified leg distance using ATR.
2. Directional structure sequence:
   - bullish: HH + HL
   - bearish: LH + LL
   - range: range high/low after valid containment.
3. Valid touch / valid break condition.
4. Active parent cycle agreement.
5. Level not obsolete.
```

## Important project law

```text
No validation = no KL label.
```

This prevents misleading output while the automatic engine improves.
