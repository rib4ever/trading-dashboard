# v1.4.1 Mitigation + Visual Engine Notes

## Ravi feedback from v1.4.0 alpha

Ravi confirmed an important positive result:

```text
The 4H confirmed KL is matching the manual key level.
The story makes more sense than v1.3.x.
```

This means the new v1.4.0 refactor direction is correct.

## Observed issues

### 1. Candidate levels remain visible after mitigation / break

Ravi observed that some 1H candidate levels are already mitigated or broken, but the script still displays them.

This is not correct.

Candidate levels should not remain on chart once price has already consumed them.

### 2. Search must move to the next valid candidate

If the latest 1H candidate high/low is mitigated or broken, the engine should not keep showing it.

It should search backward for the next available unmitigated candidate that still makes sense under NCI rules.

Expected behavior:

```text
Latest candidate is mitigated/broken -> skip it
Search previous swing candidate -> validate if active/unmitigated
Display active candidate only
```

### 3. Labels overlap

When 1H and 15M, or 5M and 15M, produce levels near the same price, labels overlap and become unreadable.

Need label staggering / offset logic.

### 4. Visual style preference

Ravi prefers:

```text
Levels drawn from the created point
Rectangular / boxed level visualization
Label on the right side of the box
If labels overlap, push one slightly to the right
```

## v1.4.1 requirements

### Mitigation filter

Candidate or KL should be considered consumed if:

```text
For resistance/high candidate:
price closed above it with buffer, or price traded through it and came back below after mitigation.

For support/low candidate:
price closed below it with buffer, or price traded through it and came back above after mitigation.
```

Simple first implementation:

```text
High candidate is obsolete if close > highCandidate + ATR buffer.
Low candidate is obsolete if close < lowCandidate - ATR buffer.
```

Later versions should add stricter NCI mitigation / retest logic.

### Candidate search depth

Search recent confirmed pivots by occurrence:

```text
occurrence 0, 1, 2, 3, 4
```

Return the first candidate that is not mitigated.

### Label staggering

Labels should use different horizontal offsets:

```text
4H = bar_index + 0
1H = bar_index + 8
15M = bar_index + 16
5M = bar_index + 24
```

When same-price overlap exists, lower layer labels should be pushed farther right.

### Rectangular box style

Use `box.new()` to create level zones from creation point to current/right side.

For alpha implementation, use a simple ATR-thin band:

```text
zone top = level + ATR * small thickness
zone bottom = level - ATR * small thickness
```

## Project law added

```text
A mitigated or broken candidate must not remain as the active candidate.
The engine must search for the next valid unmitigated candidate.
```
