# v1.4.2 Always HTF KL + NCI Zone Builder Notes

## Ravi confirmed project law

```text
A higher timeframe key level is always required.
If the latest candidate is invalid, broken, mitigated, or obsolete, the engine must search backward until it finds the latest valid NCI key level/zone.
The 4H key level must always be the master anchor of the story.
Lower timeframes are not allowed to create the main story; they can only explain, refine, or react to the 4H story.
```

## Why this version exists

v1.4.1.1 compiled and showed zones, but the story still said:

```text
No confirmed 4H parent KL yet
```

That violates the project law because the 4H master must always search for the latest active KL/zone.

## Main change

v1.4.2 always searches for the latest active 4H supply and demand zones.

If the latest high/low candidate is broken or mitigated, the engine searches backward up to the configured search depth.

## NCI zone builder alpha

This version begins the NCI zone builder:

```text
Supply zone:
- top = swing-high candle high
- bottom = derived from candle body/wick logic

Demand zone:
- bottom = swing-low candle low
- top = derived from candle body/wick logic
```

## Current special-case alpha rules

```text
Huge upper wick on supply: use top to 50% of upper wick
Huge lower wick on demand: use bottom to 50% of lower wick
Huge body: use high/open-close side depending direction
Normal candle: use body-side zone rather than raw single line
Minimum zone thickness enforced by ATR
```

## Documented NCI rules already confirmed

Having-base rules from NCI docs:

```text
Supply with base: from highest of base to farthest close price of base.
Demand with base: from lowest of base to farthest close price of base.
If base has doji candles, cover all doji.
```

These rules are documented, but the v1.4.2 alpha focuses first on swing-candle no-base zones. Having-base detection should be added next.

## SMC reference adaptation

The uploaded Flux SMC reference supports the architecture pattern:

```text
SwingData prevH/currH/prevL/currL
real-time HH/LL override
unmitigated zone search
nearest zone formatting
label grouping / segmenting idea
```

We adapt the architecture only. NCI remains the logic authority.

## Known limitations

```text

2. Obsolete-zone standards are still simplified.
3. Zone builder special cases may still need Ravi validation against the original NCI examples.
4. Child zones may still be too visually noisy; settings allow turning them off.
```
