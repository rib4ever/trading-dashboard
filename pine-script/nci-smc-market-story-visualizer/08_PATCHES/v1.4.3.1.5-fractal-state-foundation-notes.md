# v1.4.3.1.5 — Fractal State Foundation Notes

## Status
Planned implementation patch after `v1.4.3.1.4 SAFE`.

## Base to preserve
Use the stable visual family from:

```text
v1.4.3.1 preferred visual base
v1.4.3.1.3 story-based 5M execution alignment
v1.4.3.1.4 SAFE execution-zone guard
```

The patch must not reset progress, remove the visual layer, or replace the existing NCI x SMC story system with a simplified script.

## Core rule confirmed by Ravi
The same hierarchy logic must repeat on every timeframe:

```text
4H master story
→ 1H explains 4H
→ 15M explains 1H
→ 5M explains 15M / execution
```

This means the script should not apply strong verification on 4H and weak verification on 1H/15M/5M. Every timeframe must produce its own NCI state, then the story engine compares parent/child alignment.

## NCI standards to protect
From the NCI course/reference material:

1. Market structure and market cycle are used to understand trend, identify key zones for entry, stop loss, take profit and risk control.
2. Key levels must come from structure, not random pivot levels.
3. Valid breakout can be applied to:
   - recent high / low
   - key level
   - POI zone
   - range
4. Breakout standard should respect NCI pressure rules:
   - two Marubozu candles, or
   - big Marubozu + one small candle, with proper close/body conditions.
5. Pullback standard should respect NCI pressure rules:
   - two Maru candles, or
   - big Maru + one small candle, where the second candle does not show significant opposite pressure.
6. Obsolete / broken / old zones should not remain visually active as if still valid.

## Main anomaly identified from BTC 4H/1H/15M/5M screenshots
The same 4H master story appears inconsistent between chart views. Example:

```text
4H chart: 4H SUPPLY STORY ACTIVE
15M chart: 4H DEMAND STORY ACTIVE
5M chart: 4H SUPPLY STORY ACTIVE
```

For the same symbol and same indicator settings, the 4H master story must remain consistent across 4H, 1H, 15M and 5M chart views. The lower chart timeframe should not change the selected 4H master story.

### 2. Macro location engine
Add a separate macro-location layer for the master timeframe:

```text
Building KL memory
Inside 4H Supply
Inside 4H Demand
Between 4H Supply and Demand
Above 4H Supply
Below 4H Demand
```

When price is between active 4H supply and demand, the final story should prefer:

```text
4H RANGE / DECISION STORY
```

rather than forcing `4H SUPPLY STORY ACTIVE` or `4H DEMAND STORY ACTIVE` only from midpoint bias.

### 3. Repeated parent-child relation engine
Create a reusable relation function and call it three times:

```text
Relation(4H, 1H)
Relation(1H, 15M)
Relation(15M, 5M)
```

Each relation should classify the child as:

```text
continues parent
building inside parent
decision inside parent
reacts inside parent decision
counter-move
conflict
```

### 4. 5M execution zone clarity
The execution zone must be a monitor zone, not a buy/sell signal.

Recommended status labels:

```text
EXEC WAIT: 4H story building
EXEC WAIT: 1H conflict
EXEC WAIT: 15M not valid
EXEC BUILDING: no 5M zone
EXEC WATCH: inside 5M supply
EXEC WATCH: inside 5M demand
EXEC RETEST: near 5M supply/demand
EXEC INVALID: 5M zone broken
EXEC ALIGNED: monitor 5M reaction
```

### 5. Execution-zone visibility setting
Add:

```text
Execution Zone Visibility:
- Execution TF only
- 15M and below
- All timeframes
```

Default should be:

```text
15M and below
```

### 6. Mobile label lanes
Use stable forward label offsets to avoid label overlap:

```text
4H Supply/Demand: futureBars + 2 / +10

5M Supply/Demand: futureBars + 50 / +58
```
